# A06 — Controle legítimo: PDF digitalizado com camada OCR invisível

O A01 identificou quatro spans invisíveis de uma instrução adversarial.
A06 cria um **contraexemplo benigno**: um PDF cujo conteúdo visível está
rasterizado em uma imagem, mais uma camada de texto invisível **idêntica ao
conteúdo da imagem** para permitir busca e seleção.

O objetivo é demonstrar que `text_render_mode_3` não implica ataque. A06 não
contém nenhuma instrução operacional maliciosa nem depende da API Gemini.

## Execução na raiz do projeto (Windows CMD)

Depois de integrar o PR e atualizar a `main`:

```cmd
git pull origin main
.venv\Scripts\python.exe -m experiments.pdf_representation.a06_ocr
```

Arquivos sintéticos e relatório são gerados em
`data/executions/pdf_representation/a06/`, ignorado pelo Git:

- `A06_scan_only.pdf`: contém apenas a imagem rasterizada.
- `A06_scan_with_ocr.pdf`: mesma imagem, com seis linhas invisíveis alinhadas.
- `a06_report.json`: paridade visual, recuperação OCR e sinais do detector A01.

## Leitura

O resultado esperado é:
- `visual_parity = true`;
- `extraction_difference = true`;
- `hidden_spans_flagged_by_a01 = 6`;
- `scan_without_ocr_extracts_empty_text = true`;
- `ocr_recovers_all_lines = true`.

Esses sinais são **observações estruturais**, não falsos positivos de
classificação de ataque: o A01 ainda não possui tal classificador.
Eles demonstram o *risco de falso positivo* se uma futura solução converter
automaticamente invisibilidade em suspeita ou bloqueio.

```cmd
.venv\Scripts\python.exe -m pytest tests/test_pdf_representation_a06.py -q
```

**Limitação:** a camada é produzida deterministicamente a partir do texto
original, não por um OCR que possa cometer erros. A correspondência é conhecida
pela construção da fixture; não estamos validando algoritmo genérico de
alinhamento semântico entre pixels e texto.
